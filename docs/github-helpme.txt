GUIA DE GIT E GITHUB - KEEPERHUB
================================

1. CONFIGURACAO INICIAL
-----------------------
Instale o Git em https://git-scm.com/downloads.

Clone o repositorio:

git clone https://github.com/pjlkaw/keeperhub.git
cd keeperhub

Configure sua identidade uma vez por computador:

git config --global user.name "Seu Nome"
git config --global user.email "seu-email@exemplo.com"

2. COMECO DE UMA TAREFA
-----------------------
Confira o estado atual e atualize a main:

git status
git switch main
git pull origin main

Crie uma branch para a tarefa:

git switch -c feature/medicamentos-cadastro-produto

Use o formato tipo/modulo-descricao-curta. Tipos comuns: feature, fix e
docs. Se o Git da maquina nao possuir switch, use checkout no lugar.

3. COMMIT
--------
Revise as alteracoes antes de salvar:

git diff
git status

Prepare e crie um commit pequeno:

git add caminho/do/arquivo
git commit -m "feat: adicionar cadastro de medicamento"

4. ENVIAR E ABRIR PULL REQUEST
------------------------------
Envie a branch pela primeira vez com:

git push -u origin feature/medicamentos-cadastro-produto

Depois abra um Pull Request no GitHub. Descreva o que mudou, como foi
validado e inclua uma imagem quando houver alteracao visual.

O repositorio possui .github/CODEOWNERS, portanto o GitHub pode solicitar
a revisao dos responsaveis definidos nesse arquivo. A protecao da main e
a exigencia de aprovacao dependem das configuracoes do repositorio remoto.

5. ATUALIZAR UMA BRANCH
-----------------------
Com a tarefa parada ou antes do Pull Request:

git fetch origin
git switch main
git pull origin main
git switch feature/sua-branch
git merge main

Se houver conflito, resolva as marcas <<<<<<<, ======= e >>>>>>>, revise
o resultado e finalize:

git add caminho/do/arquivo
git commit

6. COMANDOS RAPIDOS
------------------
git status              Mostra o estado da copia local.
git diff                Mostra alteracoes ainda nao commitadas.
git log --oneline       Mostra o historico resumido.
git branch              Lista branches locais.
git switch nome         Troca de branch.
git pull                Baixa e integra alteracoes do remoto.
git push                Envia commits da branch atual.

7. REGRAS DO PROJETO
--------------------
- Nao commite diretamente na main.
- Trabalhe no seu modulo e altere shared/ somente quando o recurso for
  realmente compartilhado.
- Nao importe arquivos diretamente de outro modulo.
- Antes de abrir o Pull Request, confira caminhos, tema claro/escuro e
  funcionamento em um servidor local.
