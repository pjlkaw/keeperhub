KEEPERHUB - PADRONIZACAO DO PROJETO
===================================

1. NOMENCLATURA DE ARQUIVOS E PASTAS
------------------------------------
- Use nomes em minusculo, sem acentos ou espacos.
- Prefira kebab-case para novos arquivos e pastas: novo-habito.html.
- Cada modulo deve possuir modules/nome-do-modulo/index.html.
- Preserve nomes existentes quando a alteracao nao exigir renomeacao.

2. NOMENCLATURA NO JAVASCRIPT
-----------------------------
- Variaveis e funcoes: camelCase.
- Constantes imutaveis: UPPER_SNAKE_CASE quando isso melhorar a leitura.
- Use nomes em portugues quando o dominio do projeto estiver em portugues.
- Use ponto e virgula conforme o padrao predominante do arquivo.
- Strings novas em JS devem preferir aspas simples, salvo quando o contexto
  exigir outro formato.

3. ESTRUTURA E DEPENDENCIAS
---------------------------
- Um modulo nao importa arquivos diretamente de outro modulo.
- Recursos usados por mais de um modulo devem ficar em shared/.
- shared/components: fragmentos visuais HTML.
- shared/styles: tokens e estilos visuais comuns.
- shared/services: logica e integracoes compartilhadas.
- shared/utils: funcoes auxiliares puras.
- Cada modulo deve manter um script.js na raiz como inicializador do modulo.
  Os arquivos auxiliares do modulo ficam em js/ e sao importados/exportados
  por esse arquivo principal usando ES modules e async functions.
- Uma pagina pode ter varios arquivos CSS especificos; nao e obrigatorio
  concentrar todo o CSS do modulo em um unico arquivo.

4. TEMAS E CORES
----------------
- Inclua /shared/styles/variables.css antes dos estilos do modulo.
- Use os tokens do tema em vez de repetir cores fixas:
  --bg-color, --text-color, --text-muted, --card-bg e --border-color.
- Use os destaques definidos para os modulos em variables.css.
- Paginas com o botao #theme-toggle devem carregar /shared/services/theme.js.

5. PADRAO VISUAL
----------------
- Espacamentos preferenciais: 8px, 16px e 24px.
- Bordas de cards: entre 8px e 16px, salvo necessidade do componente.
- Area minima de toque: 44px por 44px.
- Garanta contraste nos temas dark e light.
- Tipografia deve seguir o estilo visual existente do modulo; nao declare
  uma fonte na documentacao se ela nao estiver configurada no CSS.

6. COMMITS
----------
Formato: tipo: descricao curta no infinitivo

feat: nova funcionalidade
fix: correcao de bug
refactor: mudanca interna sem alterar comportamento
style: ajuste visual ou formatacao
docs: documentacao
chore: configuracao, estrutura ou dependencias

Exemplos:
feat: adicionar cadastro de medicamento
fix: corrigir swipe de bons habitos
docs: atualizar estrutura do projeto

7. BRANCHES E REVISAO
---------------------
- Use tipo/modulo-descricao-curta.
- Exemplos: feature/pets-upload-foto, fix/medicamentos-swipe,
  docs/estrutura-pastas.
- Nao trabalhe diretamente na main.
- Envie mudancas por Pull Request e aguarde a revisao definida pelo projeto.
