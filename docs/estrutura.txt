KEEPERHUB - ESTRUTURA DE PASTAS
================================

keeperhub/
|
|-- index.html
|   Shell principal do HUB. Responsável pela tela de login, splash e
|   redirecionamento para o módulo escolhido pelo usuário através da
|   navegação inferior.
|
|-- manifest.json
|   Arquivo de configuração do PWA. Define informações como nome,
|   ícones, cores e modo de exibição da aplicação.
|
|-- service-worker.js
|   Responsável pelo funcionamento offline da aplicação, controlando
|   o cache dos arquivos e a comunicação/sincronização com o IndexedDB.
|
|-- README.md
|   Documentação geral do projeto, contendo informações sobre o
|   funcionamento, execução e contribuição para o projeto.
|
|-- .gitignore
|   Define os arquivos e pastas que devem ser ignorados pelo Git.
|
|-- shared/
|   Contém códigos e recursos compartilhados por TODOS os módulos.
|   Nenhum módulo deve duplicar funcionalidades que já existam aqui,
|   nem importar arquivos diretamente de outro módulo. Se uma
|   funcionalidade for comum a mais de um módulo, ela deve ficar em
|   shared/.
|   |
|   |-- components/
|   |   Componentes visuais reutilizáveis em diferentes partes do HUB,
|   |   como header, bottom-nav, modais genéricos, botões e outros
|   |   componentes padronizados da interface.
|   |
|   |-- styles/
|   |   Folhas de estilo compartilhadas por todo o sistema.
|   |   |
|   |   |-- variables.css
|   |   |   Define variáveis globais utilizadas pela aplicação, como
|   |   |   cores, tipografia (Verdana/Tahoma) e espaçamentos.
|   |   |
|   |   |-- reset.css
|   |       Responsável por padronizar e resetar os estilos
|   |       padrão aplicados pelos navegadores.
|   |
|   |-- services/
|   |   Serviços e integrações compartilhados entre os módulos.
|   |   |
|   |   |-- auth.js
|   |   |   Responsável pela autenticação através do Google.
|   |   |
|   |   |-- db.js
|   |   |   Fornece uma camada de acesso e comunicação com o
|   |   |   IndexedDB.
|   |   |
|   |   |-- notifications.js
|   |       Responsável pelo gerenciamento de notificações push
|   |       e alertas da aplicação.
|   |
|   |-- utils/
|       Funções auxiliares e utilitários genéricos utilizados por
|       diferentes partes do sistema, como formatação de datas,
|       validações de formulários e outros helpers.
|
|-- modules/
|   Contém os módulos independentes que compõem o HUB. Cada módulo
|   possui responsabilidade própria e deve funcionar de forma
|   independente dos demais.
|
|   Um módulo NUNCA deve importar arquivos diretamente de outro módulo.
|   Quando precisar de uma funcionalidade compartilhada, deve utilizar
|   os recursos disponíveis em shared/.
|   |
|   |-- despensa/
|   |   Controle de estoque e comparação de preços.
|   |
|   |-- pets/
|   |   Gerenciamento da rotina e dos cuidados com os pets.
|   |
|   |-- metas/
|   |   Gerenciamento de metas pessoais, financeiras e da área Solitude.
|   |
|   |-- financas/
|   |   Controle financeiro baseado no método 50-30-20.
|   |
|   |-- medicamentos/
|       Controle de validade, estoque e alertas de medicamentos.
|
|-- docs/
    Documentação complementar do projeto, incluindo especificações
    técnicas, estrutura do projeto e outros materiais de referência
    utilizados pela equipe.
